# PackSmart AI

A smarter packing list for every journey.

Enter your trip details and PackSmart AI returns a categorised, editable packing checklist generated by Claude. Tick items off, add your own, remove what you don't need, and print or save the list as a PDF. Progress is kept in your browser.

Built with Next.js (App Router), TypeScript, Tailwind CSS, the official Anthropic TypeScript SDK, Zod, and Lucide icons. No database.

## Requirements

- Node.js 18.18 or newer (Node 20+ recommended)
- An Anthropic API key from https://console.anthropic.com

## 1. Get the project

If you're starting from this folder, skip ahead to step 2. To scaffold an equivalent project from scratch:

```bash
npx create-next-app@latest packsmart-ai --typescript --tailwind --app --eslint --no-src-dir --import-alias "@/*"
cd packsmart-ai
```

Then copy the `app/`, `components/`, and `lib/` folders and the config files from this repository over the generated ones.

## 2. Install dependencies

```bash
npm install
```

The application dependencies specifically are:

```bash
npm install @anthropic-ai/sdk zod lucide-react
```

Tailwind is wired up through `tailwind.config.ts`, `postcss.config.mjs`, and the `@tailwind` directives at the top of `app/globals.css`. If you scaffolded with `--tailwind`, those are already installed; otherwise:

```bash
npm install -D tailwindcss postcss autoprefixer
```

## 3. Create `.env.local`

```bash
cp .env.example .env.local
```

Open `.env.local` and add your real key:

```
ANTHROPIC_API_KEY=sk-ant-...
ANTHROPIC_MODEL=claude-sonnet-5
```

`ANTHROPIC_MODEL` is optional. If you leave it out, the route falls back to the default set in `app/api/generate-packing-list/route.ts`. Check the Anthropic model documentation for the identifier you want and change this one line — nothing else in the code needs to change.

`.env.local` is already listed in `.gitignore`. Never commit it, and never rename the key to `NEXT_PUBLIC_ANTHROPIC_API_KEY` — that would ship your key to every visitor's browser.

## 4. Run it

```bash
npm run dev
```

Open http://localhost:3000.

## 5. Test a real request

Fill in the form — for example Lagos, Nigeria, 5 days, Holiday, Hot and humid, Carry-on only, no laundry, Balanced, with Swimming and Sightseeing ticked — and press **Generate my smart packing list**. Within a few seconds you should see a titled checklist with categories, quantity badges, tips, and a reminders card.

You can also call the route directly:

```bash
curl -X POST http://localhost:3000/api/generate-packing-list \
  -H 'Content-Type: application/json' \
  -d '{"destination":"Lagos, Nigeria","days":5,"tripType":"Holiday","climate":"Hot and humid","luggage":"Carry-on only","laundry":"No laundry access","packingStyle":"Balanced","activities":["Swimming"]}'
```

## What happens without an API key

The route returns HTTP 500 with a JSON body:

```json
{ "ok": false, "code": "missing_api_key", "message": "The server is missing ANTHROPIC_API_KEY. Add it to .env.local and restart the dev server." }
```

The UI shows an error card with a **Try again** button rather than failing silently. If the key is present but rejected by Anthropic, you get the same status with a different message. Provider error details are logged server-side only and never returned to the browser.

Remember to restart `npm run dev` after editing `.env.local` — Next.js reads environment files at startup.

## Deploying

The app runs anywhere that supports Node. On Vercel:

1. Push the repository and import it.
2. In **Project Settings → Environment Variables**, add `ANTHROPIC_API_KEY` (and optionally `ANTHROPIC_MODEL`) as plain server-side variables for the environments you need.
3. Deploy.

Do not use the `NEXT_PUBLIC_` prefix for either variable. The route handler is pinned to `runtime = 'nodejs'` because the Anthropic SDK is not Edge-compatible.

### Rate limiting in production

`app/api/generate-packing-list/route.ts` includes a fixed-window in-memory limiter of 10 requests per 15 minutes per IP. It's there to stop casual abuse in development and on a single small instance. It resets on every cold start and is not shared between serverless invocations or across multiple containers, so under real traffic it enforces very little. Replace it with Redis, Upstash, Vercel KV, or your platform's edge rate limiting before launch.

The limiter key comes from `x-forwarded-for`, falling back to `x-real-ip`. Managed platforms overwrite that header, so the left-most entry is trustworthy there. If you self-host and expose Next.js directly, a client can forge it — put a proxy in front and read only a header your proxy sets.

### Why there's no database

The current trip lives in `localStorage` under a single key, `packsmart_ai_current_trip`, so one person on one browser needs no backend storage. You would need a database to add accounts, sync across devices, share lists with travel companions, keep a history of past trips, or bill for anything.

## How it's put together

```
app/api/generate-packing-list/route.ts   Server-only. Validates input, calls Claude, validates output.
app/page.tsx                             Client. Form/result state, localStorage, toasts, dialogs.
components/PackingForm.tsx               Controlled form with inline validation.
components/PackingResults.tsx            Checklist, progress, custom items, actions.
components/TripSummary.tsx               Trip detail chips (server-safe, no "use client").
lib/schemas.ts                           Zod: request, model output, stored result.
lib/types.ts                             Shared types and option constants.
lib/storage.ts                           Guarded localStorage helpers.
lib/utils.ts                             IDs, icon mapping, fence stripping, progress.
```

The API key is read only as `process.env.ANTHROPIC_API_KEY`, only inside the route handler. The Anthropic SDK is never imported by a client component.

Claude is asked for `name`, `quantity`, and `tip` only. The server assigns every `id`, forces `checked: false`, sets `custom`, picks category icons from application code, deduplicates items by a normalised name within and across categories, and sorts categories into a fixed order. Model output is parsed defensively (markdown fences stripped, JSON extracted) and validated with Zod before anything reaches the browser.

Free-text fields are cleaned of control characters, collapsed, and length-capped. The special-requirements text is explicitly framed to Claude as user data rather than instructions.

## Testing checklist

**Form validation**
- Submit with an empty destination, and with a one-character destination. Both should block with an inline message and move focus to the field.
- Enter 0 days and 61 days. Both should block.
- Submit with no activities selected. This should work.
- Type past 500 characters in the special requirements box; the counter should stop you.

**Generation**
- Generate a list and confirm the title names your destination and duration.
- Confirm quantity badges appear where Claude supplied one, and that tips render underneath item names.
- Check that the reminders card mentions verifying things independently rather than asserting travel facts.

**Persistence**
- Tick several items, refresh the page. The ticks should survive.
- Remove an item and add a custom one (it gets an "Added by you" badge), then refresh again.
- Press **Untick everything** and confirm items remain but are cleared.
- Press **Clear packed items** and confirm ticked items are removed.
- Press **New trip**, confirm the dialog appears, cancel it, then confirm it and check you're returned to an empty form.

**Errors**
- Rename `ANTHROPIC_API_KEY` in `.env.local`, restart, and generate. You should see the error card, not a crash.
- Stop the dev server mid-request, or go offline in DevTools, and confirm you get the network error message.
- Submit 11 requests inside 15 minutes and confirm the 11th returns 429 with a `Retry-After` header.
- `curl` the route with `GET` (405) and without a JSON content type (415).

**Interface**
- Print preview the result page: the form, buttons, header, and collapse chevrons should disappear, leaving title, summary, chips, categories, and reminders.
- Tab through the whole page and confirm every control shows a visible focus ring.
- Check the layout at 375px, 768px, and 1280px wide.
- Turn on reduced motion and confirm transitions stop.

## Verified

`npm run typecheck`, `npm run lint`, and `npm run build` all pass clean on Next 16 with React 19. The error paths above (missing key, rejected key, invalid body, wrong method, wrong content type, rate limit) were exercised against a running production build.
